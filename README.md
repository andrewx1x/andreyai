# Сводка — Telegram-боты для аналитики и рекламы

Система из 4 Telegram-ботов и веб-дашборда для автоматизированных отчётов по Яндекс.Метрике и Яндекс.Директу.

**Целевая аудитория:** владельцы сайтов и рекламодатели, которые хотят контролировать трафик и рекламные бюджеты без ежедневного входа в кабинеты Яндекса.

**Ценностное предложение:** бот сам присылает в Telegram понятный отчёт с выводами и предупреждает, если что-то пошло не так (упал трафик, вырос расход, просели конверсии).

---

## 1. Сводка.Трафик (@TrafficInsightBot_bot)

**Что делает:** подключается к счётчику Яндекс.Метрики пользователя и ежедневно присылает отчёт по трафику прямо в Telegram. Если показатели резко меняются — бот сообщает об этом алертом.

### Путь пользователя

1. Пользователь нажимает `/start` → видит приветствие и кнопку **«Начать настройку»**
2. Нажимает **«Получить токен»** → переходит на страницу Яндекса, даёт доступ на чтение, копирует код
3. Вставляет код в чат → бот проверяет токен и шифрует его (AES-256-GCM)
4. Бот загружает список счётчиков → пользователь выбирает нужный
5. Бот загружает цели счётчика → пользователь отмечает до 5 целей и выбирает главную
6. Пользователь выбирает метрики для отчёта (визиты, пользователи, отказы и т.д.)
7. Настраивает расписание: ежедневно / еженедельно, время, таймзону
8. Включает/выключает алерты и выбирает правила (падение трафика, рост отказов, падение главной цели)
9. Подтверждает настройки → бот переходит в рабочий режим

### Рабочий режим

- По расписанию (утро/вечер) бот отправляет отчёт:
  - Текущий день vs среднее за 7 предыдущих дней
  - Метрики: визиты, цели, отказы, источники трафика
  - Цветовая индикация: рост / норма / падение
  - Автоматический вывод: что изменилось и что стоит проверить
- Каждые 15 минут бот проверяет алерты:
  - Трафик упал более чем на X% → сообщение-алерт
  - Главная цель просела → сообщение-алерт
  - Отказы выросли → сообщение-алерт
  - Cooldown: повторный алерт того же типа не чаще 1 раза в 24 часа
- При истечении OAuth-токена бот уведомляет и предлагает обновить доступ

### Кнопки в рабочем режиме

| Кнопка | Действие |
|--------|----------|
| **Отчёт сейчас** | Принудительно собирает и отправляет отчёт |
| **Настройки** | Меню изменения метрик, расписания, алертов |
| **Помощь** | Открывает бот поддержки с контекстом |

### Что содержит отчёт (пример)

```
📊 Отчёт по сайту example.com
📅 21 февраля 2026 vs среднее за 7 дней

👥 Визиты: 1 240 (↑ +12%)
🎯 Заявка: 28 (↓ −8%)
🎯 Звонок: 15 (↑ +25%)
📉 Отказы: 18.2% (норма)
🔍 Поиск: 680 | 💬 Прямые: 320 | 🔗 Ссылки: 240

💡 Вывод: трафик растёт, но конверсия в заявки снизилась.
   Проверьте форму заявки и скорость загрузки посадочных.
```

## 2. Сводка.Реклама (@AdsRadar_bot)

**Что делает:** подключается к аккаунту Яндекс.Директа и ежедневно присылает отчёт по рекламным кампаниям. Предупреждает если бюджет расходуется слишком быстро, CPA растёт или CTR падает.

### Путь пользователя

1. Пользователь нажимает `/start` → приветствие и кнопка **«Начать настройку»**
2. Нажимает **«Получить токен»** → OAuth Яндекса → копирует код
3. Вводит логин аккаунта Яндекс.Директа (под которым ведётся реклама)
4. Бот загружает кампании → пользователь выбирает: все кампании или конкретные
5. Если выбраны конкретные — отмечает нужные из списка
6. Выбирает метрики: показы, клики, CTR, расход, CPC, конверсии, CPA
7. Выбирает период сравнения (день / неделя / месяц) и расписание отчётов
8. Настраивает алерты: рост расхода >50%, падение кликов >30%, падение CTR >20%, рост CPA >50%
9. Подтверждает → бот работает

### Рабочий режим

- По расписанию отправляет отчёт:
  - Текущий период vs предыдущий (день/неделя/месяц)
  - Метрики: показы, клики, CTR, расход, CPC, конверсии, CPA
  - Топ кампаний по расходу
  - Автоматический вывод с рекомендацией
- Каждые 15 минут проверяет алерты:
  - Рост расхода → алерт
  - Падение CTR → алерт
  - Рост CPA → алерт
  - Падение кликов → алерт
  - Cooldown 24 часа между повторными алертами
- При истечении OAuth-токена → уведомление с кнопкой обновления

### Кнопки в рабочем режиме

| Кнопка | Действие |
|--------|----------|
| **Отчёт сейчас** | Принудительный отчёт |
| **Открыть дашборд** | Веб-дашборд с графиками (WebApp) |
| **Настройки** | Изменение кампаний, метрик, алертов |
| **Помощь** | Бот поддержки с контекстом |

### Что содержит отчёт (пример)

```
📊 Отчёт по рекламе | Яндекс Директ
📅 21 февраля 2026 vs 20 февраля

💰 Расход: 4 820 ₽ (↑ +15%)
👁 Показы: 12 400 (↑ +8%)
👆 Клики: 340 (↓ −5%)
📈 CTR: 2.74% (↓ −12%)
💸 CPC: 14.2 ₽ (↑ +21%)
🎯 Конверсии: 12 (↓ −20%)
💵 CPA: 401 ₽ (↑ +44%)

🏆 Топ по расходу:
  1. Поиск — Ремонт квартир: 2 100 ₽
  2. РСЯ — Ретаргетинг: 1 540 ₽
  3. Поиск — Дизайн интерьера: 1 180 ₽

⚠️ Вывод: CPA вырос на 44%, клики снизились при росте расхода.
   Проверьте ставки в кампании «Поиск — Ремонт квартир»
   и качество трафика из РСЯ.
```

## 3. Сводка.Демо (@PulseDemo_bot)

**Что делает:** показывает примеры отчётов и алертов без подключения к реальным данным. Нужен для того, чтобы потенциальный клиент мог оценить продукт перед покупкой.

### Путь пользователя

1. `/start` → приветствие **«СВОДКА — ДЕМО»** с описанием
2. Кнопка **«Выбрать продукт»** → два варианта: Трафик или Реклама
3. Выбирает продукт → бот показывает фиксированный демо-отчёт с тестовыми данными
4. Кнопки навигации:
   - **Посмотреть отчёт** — пример ежедневного отчёта
   - **Посмотреть алерт** — пример алерта при проблеме
   - **Изменить метрики** — демо-экран настройки метрик
   - **Изменить время** — демо-экран настройки расписания
   - **Видео** — демо-видео работы продукта
5. Финальный экран с CTA:
   - Кнопка перехода на лендинг
   - Кнопка перехода в рабочий бот
   - Кнопка открытия демо-дашборда (для Директа)

### Особенности

- Не ходит ни в какие внешние API
- Все данные в отчётах — тестовые (захардкожены)
- Состояние хранится в памяти Worker (не в БД), сбрасывается при деплое
- Цель — показать ценность продукта и сконвертировать в платного пользователя

## 4. Сводка.Поддержка (@PulseAssist_bot)

**Что делает:** принимает вопросы, баг-репорты и предложения от пользователей. Каждый пользователь получает отдельный тикет, сообщения пробрасываются в админ-группу.

### Путь пользователя

1. Пользователь нажимает **«Помощь»** в любом из ботов → открывается бот поддержки с deep-link контекстом (бот знает, откуда пришёл пользователь)
2. Или пишет `/start` напрямую
3. Бот приветствует и просит описать проблему
4. Пользователь пишет текст / отправляет скриншот
5. Бот создаёт Forum Topic в админ-группе с именем и контекстом пользователя
6. Все последующие сообщения пробрасываются в обе стороны: пользователь ↔ админ
7. Админ отвечает в топике → пользователь получает ответ в личный чат
8. Админ пишет `/close` → тикет закрывается, пользователь получает сообщение с кнопками возврата в основные боты

### Автоматика

- **Нерабочее время:** бот отправляет автоответ «Мы ответим в рабочее время» с cooldown (не спамит)
- **Срочность:** если в сообщении есть слова «срочно», «urgent», «asap» — админы получают отдельное уведомление
- **Ночные обращения:** отдельное уведомление админам

## Веб-дашборд

Отдельное веб-приложение (React) для визуализации данных Яндекс.Директа.

### Что показывает

- KPI-карточки: расход, клики, конверсии, CPA
- Таблица по каналам: поиск, РСЯ, карты
- Графики помесячной динамики
- Сравнение с предыдущим периодом
- Блок автоматических выводов

### Как работает

- Открывается по кнопке **«Открыть дашборд»** из бота Рекламы
- Авторизация через Telegram WebApp (токен сессии)
- Без токена показывает демо-данные
- REST API: `GET /api/dashboard/data`

## Стек технологий

- **Runtime:** Cloudflare Workers (serverless, edge)
- **Язык:** TypeScript (ES2022)
- **База данных:** Cloudflare D1 (SQLite)
- **Сборка:** esbuild через Wrangler
- **Фронтенд дашборда:** React + Vite + Tailwind CSS
- **Лендинги:** HTML + Tailwind CDN + Inter
- **API:** Yandex.Metrika API v1, Yandex.Direct Reports API v5
- **Шифрование:** AES-256-GCM (OAuth-токены), HMAC-SHA256 (сессии)

## Архитектура

Все 4 бота + API дашборда работают в одном Cloudflare Worker.

### Роутинг

```
POST /webhook/metrika   → бот Трафик
POST /webhook/direct    → бот Реклама
POST /webhook/support   → бот Поддержка
POST /webhook/landing   → демо-бот
GET  /api/dashboard/*   → REST API дашборда
GET  /api/health        → health check
```

### Cron-триггеры

| Расписание | Время (МСК) | Действие |
|-----------|-------------|----------|
| `0 7 * * *` | 10:00 | Утренние отчёты (Метрика + Директ) |
| `0 16 * * *` | 19:00 | Вечерние отчёты |
| `*/15 * * * *` | каждые 15 мин | Проверка алертов (cooldown 24ч) |

### Визард настройки (7 шагов)

1. OAuth-токен (шифруется AES-256-GCM, хранится в D1)
2. Выбор счётчика / логина + кампаний
3. Выбор целей / метрик
4. Настройка расписания (время, частота, таймзона)
5. Настройка алертов (правила и пороги)
6. Подтверждение всех настроек
7. Активация — бот начинает работать

## База данных (D1)

| Таблица | Назначение |
|---------|-----------|
| `users` | Пользователи (telegram_id, язык, таймзона) |
| `chats` | Сессии по ботам (состояние визарда, шаг настройки) |
| `tokens` | Зашифрованные OAuth-токены (AES-256-GCM) |
| `bot_settings` | Настройки ботов: метрики, расписание, алерты (JSON) |
| `subscriptions` | Подписки пользователей (статус, дата окончания) |
| `alert_cooldowns` | Cooldown алертов — не чаще 1 раза в 24ч на тип |
| `support_tickets` | Тикеты поддержки (привязка к Forum Topics) |
| `dashboard_sessions` | Сессии веб-дашборда (TTL 30 мин) |
| `report_cache` | Кэш отчётов |

## Безопасность

- OAuth-токены шифруются AES-256-GCM перед сохранением в БД
- Доступ к данным Яндекса только на чтение (read-only)
- Сервис работает с данными пользователя по его поручению
- Webhook-секрет для верификации запросов от Telegram
- Сессии дашборда с TTL и подписью HMAC-SHA256
- CORS ограничен доменами Telegram
- Секреты хранятся в Cloudflare Workers Secrets, не в коде
- Данные показываются только тому пользователю, который дал доступ
- Данные не передаются третьим лицам
